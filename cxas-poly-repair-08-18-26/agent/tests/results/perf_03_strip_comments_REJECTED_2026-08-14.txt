SCOPE, after a correction. The first attempt stripped every emitted .py, which was wrong:
a tool offered to the MODEL carries its docstring into the tool schema and
`docstring_args` parses arg descriptions out of it, so prose in a model-facing tool is
product, not overhead. Rescoped to bodies the model provably cannot see, taken from the
runtime hide list in the emitted before_model callback rather than from assumption:

WHY IT FAILED, WHICH IS THE USEFUL PART. A 36% smaller engine body bought 3.6% less time.
So per-call cost does NOT track source BYTES — it tracks SYNTACTIC COMPLEXITY. Comments
are discarded by the tokenizer almost for free and produce zero AST nodes; a nested dict
literal costs thousands of nodes to build and emit bytecode for.

That retires the "~14ms + 0.44ms per KB" fit from the original diagnosis. The fit was real
but coincidental: across the tools sampled (939B verdict, 59KB slot_intake, 266KB
repair_dag, 528KB engine) size happened to correlate with node count. Change 2 worked
because it removed 180,000 AST nodes, not because it removed 180KB — the 266KB literal
became one string constant. Change 3 removed bytes without removing nodes, and bought
nothing.

CONSEQUENCE FOR THE REMAINING WORK. Stop proposing size reductions. The lever is either
FEWER invocations (change 4: pass the config through input_data so the dag tool is not
re-invoked; change 5: batch independent task dispatches into one preempt) or less work
per invocation. "Tree-shake the 528KB engine", previously ranked as ~1200ms, should be
expected to behave like this change and is dropped unless it also removes node count.

ALSO NOTE the platform was materially busier during this batch than during change 2's
(turn medians ~9.2s against ~6.7s; engine 248ms/call against 171ms). Arms were alternated,
so the comparison holds, but absolute numbers are NOT comparable across result files.

WHAT WAS GIVEN UP BY REVERTING: nothing measurable. What was avoided: a narrowed manifest
guarantee (comment-only edits to the bundle would have stopped counting as drift), an
allowlist needing to stay in step with the runtime hide list forever, and a new module.
Real complexity for an unmeasurable gain.
